## Findings considered and NOT planned

Surfaced by the audit, deliberately left out of this batch (recorded so they
aren't re-audited). Any of these can become a plan on request.

**Defects not planned:**
- **Notification fan-out bypasses the outbox (dual write)** — `cancel_mailing.py`
  and `send_schedule_change_notifications.py` publish directly after commit; a
  crash between commit and publish loses the event. MED risk, entangled with 007;
  natural follow-up once 006/007 land.
- **Outbox relay holds row locks + a DB connection across NATS I/O for a whole
  batch** — up to `batch_size × 10s` under a slow broker. MED effort/risk;
  restructure fetch→publish→mark. Worth doing but not top-leverage.
- **Client IP for rate-limiting trusts the leftmost `X-Forwarded-For`** —
  spoofable; the deployed `etc/caddy/Caddyfile` lacks `trusted_proxies`. Bounded
  by the non-spoofable per-email login cap. Fix spans app + deploy config
  (topology-dependent) — do deliberately with the deployment owner.
- **Dead injections in the subscriptions interactors** — `create_subscription`
  injects an unused `schedule_gateway` (likely a *missing* event-existence check)
  and `user_gateway`; `delete_subscription` injects an unused `user_gateway`. S
  effort; Plan 006 documents the missing validation as current behavior.
- **`handleLogout` online path has no try/catch** (`AppNavbar.svelte:51`) — a
  network blip mid-logout leaves the user visually logged in. S, frontend.
- **Frontend build-chain advisories** — `nanoid <3.3.18` (high), `cookie <0.7.0`
  (low), transitive under SvelteKit/Sentry/vite; build-path only. `pnpm update`
  or a `pnpm.overrides` pin. Trivial hygiene.
- **`just ci` referenced by `.github/workflows/ci.yml` but no such recipe
  exists** — onboarding friction. Add a `ci:` recipe or fix the comment. S, DX.
- **Frontend micro-perf / test gaps** — `EventCard.svelte:30` builds one API
  client per schedule row; `offlineCache.ts` / `events.svelte.ts` /
  `validation.ts` / `feed.ts` / `cooldown.svelte.ts` have no Vitest coverage.
  Low individual leverage.
- **Docs drift** — `docs/testing.md:293` cites `utils/cooldown.svelte.ts`; the
  file is `services/cooldown.svelte.ts`. One-line fix.

**Direction (options for the maintainer, not defects):**
- **Ticket revocation/refund lifecycle** — three converging TODOs
  (`tickets_import.py:22-27`, `sync_tickets.py:47`, `webhooks.py:26-28`); the
  ticket flow is additive-only today. Wants a design/spike plan (TicketsCloud
  reuses ids, so naive deletion is unsafe). HIGH-confidence grounding.
- **Schedule export** — import exists, export doesn't; organizers edit live but
  can't get the schedule back out. The parser's column contract already defines
  the shape. MED confidence.
- **Webhook event-type routing** — `webhooks.py` parses `payload.type` but
  ignores it; one dispatch away, and the natural home for the revocation branch.
  Sequence with the revocation work, not speculatively.

**Cleared (not findings):** no god modules; CORS is an explicit allowlist (never
`*`); the notification `{@html}` sink is sanitized at a single `nh3` chokepoint;
backend `pip-audit` is clean; the TicketsCloud webhook auth is constant-time and
fail-closed; ticket-linking concurrency is backstopped by `FOR UPDATE` +
`uq_tickets_used_by_user_id`; `skip_validation=True` in the test container is
intentional; the three vendored skills that contradict AGENTS.md are kept on
purpose. Session cookies already set HttpOnly + SameSite=Lax; the app already
fails closed on `DEBUG__ENABLED` in prod (Plan 004 extends that pattern to
`cookie_secure`).
