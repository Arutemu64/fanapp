# ADR-0021: TanStack Query for server state, persisted to IndexedDB

- **Status:** Accepted
- **Date:** 2026-10-13
- **Deciders:** Project maintainers

## Context

The SPA read every screen's data in a SvelteKit `load`. Each read that had to
work offline went through a hand-written cache (`offlineCache.ts`: a
`fetchWithCache` per page with user/universal scopes, a logout epoch, timeout
budgets and a stale flag). `depends`/`invalidate` keys refreshed it after
mutations and SSE events, and a debounced `refreshAll` caught up after a
reconnect. Pagination was a hand-written `PaginatedFeed` remounted through
snapshot keys, and the unread badge was a hand-written coalescing service.

Every navigation waited on the network: a `load` blocked first paint until
its fetch answered or timed out, and a page only showed its cached copy once
the fetch had failed. On a venue's congested mobile network that is the
common case. The attendees need stale-while-revalidate: show what was last
seen at once, refresh behind it.

## Decision

We will hold all server state in TanStack Query (`@tanstack/svelte-query` 6,
Svelte 5 runes), with the query options and keys generated by hey-api's
[`@tanstack/svelte-query` plugin](https://heyapi.dev/openapi-ts/plugins/tanstack-query),
and stay on TanStack's defaults (`staleTime` 0; refetch on mount, focus and
reconnect; three retries) except where persistence requires otherwise.

- **One cache, created in the root load.** `+layout.ts` creates the
  `QueryClient` and returns it as load data
  ([TanStack's SvelteKit setup](https://tanstack.com/query/latest/docs/framework/svelte/ssr)),
  never as a module singleton. Nothing re-runs that load, so SvelteKit's
  `depends`/`invalidate`/`invalidateAll`/`refreshAll` are not used at all.
- **Persisted whole to IndexedDB.** `persistQueryClient` with
  `createAsyncStoragePersister` over `idb-keyval` (already a dependency) restores
  the cache before any guard runs. `gcTime` equals the persister's 24h `maxAge`,
  as [its docs](https://tanstack.com/query/latest/docs/framework/react/plugins/persistQueryClient)
  require, and the build `version` is the `buster`.
- **One scope.** There is no per-user partition. At logout or session expiry
  the user query turns `null`, and once the screen shows the guest state
  `forgetSession` removes every unused query and invalidates the rest.
- **Reachability drives `onlineManager`.** The app's active health probe
  replaces TanStack's `navigator.onLine` listener, so offline queries pause and
  `refetchOnReconnect` is the reconnect catch-up.
- **Loads guard and prefetch.** They read identity from the cache, set navbar
  data, and start the page's query early (SvelteKit preloads on hover/tap).
  They await a query only when the page can't render without it.
- **Invalidation is TanStack's.** Mutations and a single SSE→query-key map in
  the root layout call `queryClient.invalidateQueries`.
- **One configured API client.** hey-api's `runtimeConfigPath` configures the
  generated singleton client, which holds configuration only. This replaces
  ADR-0017's per-call `createApiClient()`; its interceptors are registered and
  torn down by the root layout.

## Consequences

- Cached screens paint at once, offline included, and revalidate behind it.
  Offline support is no longer per-page code: every query is saved.
- About 1,350 net lines of hand-written loading, caching, pagination and refresh
  code are gone. In their place are three dependencies:
  `@tanstack/svelte-query`, `@tanstack/svelte-query-persist-client` and
  `@tanstack/query-async-storage-persister`.
- A page now owns its pending and error states: a skeleton or spinner, and an
  inline `ErrorState` built from `query.error`. Query errors carry the API
  error body without the HTTP status, so a "not found" is matched by `code`.
- A cached copy expires 24h after the app last saved its cache, where the old
  IndexedDB entries never expired.
- Data that must not be shown stale offline (voting) is still cached, so each
  such surface must hide it offline itself.
- Do not call SvelteKit `invalidateAll`/`refreshAll` or make the root load
  depend on anything. Re-running it would replace the cache.

## Alternatives considered

- **Keep the hand-written cache and make it SWR.** Rejected: it would grow into
  a partial query library (dedup, retries, pagination, focus/reconnect refetch,
  persistence), the code this change deletes.
- **`PersistQueryClientProvider` from `@tanstack/svelte-query-persist-client`.**
  Rejected: it restores in an effect after the first render, too late for the
  guard loads that read identity from the cache. The root load restores first
  instead; the package is kept for the `persistQueryClient` it re-exports.
- **Per-query persistence (`experimental_createQueryPersister`).** Rejected:
  experimental, and one entry for the whole cache is enough at this size.
- **Generated mutation options (`createMutation`).** Not adopted for now:
  mutations stay plain SDK calls with their existing inline error handling.
