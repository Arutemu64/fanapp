# Design Guidelines

- Prioritize official Flowbite-Svelte components (e.g., Card, Modal, BottomNav, Avatar, Badge, Button).
- Do not build custom UI elements from scratch if a Flowbite-Svelte equivalent exists.
- Import standard icons exclusively from flowbite-svelte-icons.
- Write all placeholder text, labels in Russian to fit the application domain.

## Component-Specific Rules

- Card Padding: The <Card> component in Flowbite-Svelte often requires explicit padding management when generated by an LLM. Always ensure content does not touch the edges by either defining the built-in padding prop (e.g., padding="xl", padding="sm") or by wrapping the internal content within a <div class="p-4"> or <div class="p-5">.

## Mobile-First Layout

- Design strictly for mobile screens first.
- Scale up using sm: or md: prefixes only when explicitly required.
- Ensure primary buttons are at least 44px in height/width to prevent "fat-finger" errors.
- Don't place interactive elements too close to the screen edges where phone cases or system gestures (like "swipe to go back") might interfere.

## Text Sizes

- Headers text: text-xl or text-2xl
- Card Titles: text-lg font-bold
- Body Text: text-base
- Caption: text-sm
- Use leading-relaxed for descriptions to prevent lines of text from blurring together.

## Light & Dark Mode

- Every component must support both modes using Tailwind's dark: modifier.

## Code Quality & Styling Rules

- Use standard Tailwind utility classes for all sizing, spacing, and typography (e.g., p-4, w-full, text-sm).
- Never use complex, static, or arbitrary Tailwind values (e.g., w-[317px], mt-[15px]) unless strictly required to match an external fixed-size asset.
- Group layout elements cleanly using flex, flex-col, and gap-4 rather than relying heavily on explicit margins.
- Keep Svelte template files clean by destructuring props and utilizing Svelte's native logic blocks (#if, #each).
